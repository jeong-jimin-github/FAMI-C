# NES 하드웨어 제약

런타임이 대부분 가려 주지만, **설계 단계에서 알아야 피할 수 있는 것들**이 남아 있다.
여기 있는 건 전부 "몰랐다가 나중에 다시 만들게 되는" 종류다.

---

## 1. 예산 한눈에

| 자원 | 크기 | 넘으면 |
|------|------|--------|
| PRG ROM | 32KB | `E0702` |
| CHR 타일 | 256장 (배경+스프라이트 공유) | `E0507` (무엇이 몇 장 썼는지 표로) |
| 일반 RAM | 1280바이트 | `E0309` |
| 제로페이지 | 240바이트 (런타임이 대부분 사용) | `E0309` |
| 스프라이트 | 화면 64장, **한 가로줄 8장** | 실기에서 깜빡임 (에뮬레이터는 재현 안 함) |
| 배경 팔레트 | 4개 x 3색 + 공용 배경색 1 | — |
| 스프라이트 팔레트 | 4개 x 3색 + 투명 | — |
| 프레임당 배경 갱신 | 타일 32장 (자동 큐) | 다음 프레임으로 밀린다 |

빌드마다 출력된다:
```
OK  PRG 32768/32768 바이트  타일 81/256  RAM 743/1280  ZP 77/240
```

---

## 2. 색: 16x16 칸 단위로만 정할 수 있다

**이게 NES에서 가장 자주 발목을 잡는다.**

타일은 8x8이지만, 어떤 팔레트를 쓸지는 **16x16 칸(타일 4장)마다 하나**만 고를 수 있다.
즉 붙어 있는 8x8 타일 넷은 반드시 같은 배경 팔레트를 쓴다.

설계에 미치는 영향:

- 16x16 칸에 맞춰 게임을 짜면 문제가 없다 → `asset metatile` + `bg_meta`.
- 8x8 단위로 색을 다르게 하고 싶다면 **불가능하다.** 색이 아니라 **무늬**로 구분하라.
  `examples/tetris.c`가 그 예다: 조각 7개를 색이 아니라 각기 다른 무늬로 구분하고,
  색은 레벨을 따라 바꾼다.
- 스프라이트는 스프라이트마다 팔레트를 고를 수 있다. 색이 중요한 것은 스프라이트로.

한 팔레트는 색 3개 + 공용 배경색 1개다. 배경색(첫 칸)은 8개 팔레트가 **전부 공유**한다.
다르게 쓰면 컴파일러가 맞추고 `W0903`으로 알려준다.

---

## 3. vblank는 짧다

화면을 그리지 않는 시간은 프레임의 약 8%다. 그 사이에만 VRAM에 안전하게 쓸 수 있다.

**런타임이 처리해 준다:**
- `bg_tile()` 등은 렌더링 중이면 큐에 넣고, NMI가 프레임당 32개씩 흘려보낸다.
- 큐가 차면 NMI가 비울 때까지 알아서 기다린다. 화면은 깨지지 않고, 반영이 몇 프레임 늦을 뿐이다.
- `bg_clear()`와 `bg_map()`은 내부에서 렌더링을 껐다가 원래대로 되돌린다.

**직접 신경 쓸 일:**
- 화면을 통째로 다시 그릴 때는 `ppu_off(); ...; ppu_on();`으로 감싸라.
  큐로 960장을 보내면 30프레임이 걸린다.
- 팔레트 교체는 `pal_load()`/`pal_set()`을 부르면 다음 NMI에 자동 반영된다.

---

## 4. 스프라이트

- 16x16 캐릭터 하나 = 스프라이트 **4장**. 64장이면 캐릭터 16개.
- **한 가로줄에 8장**을 넘으면 실기에서 9번째부터 사라진다(보통 깜빡이게 만든다).
  적을 세로로 흩어 배치하면 피할 수 있다.
- OAM은 매 프레임 새로 채운다. `spr_clear()` → `spr*()` 순서를 지켜라.
- 스프라이트 Y는 하드웨어상 1픽셀 아래에 그려진다. 런타임이 보정하므로
  `spr(x, y, ...)`의 `y`는 화면에 보이는 위치 그대로다.
- 화면 위쪽 1픽셀 줄에는 스프라이트를 놓을 수 없다(하드웨어 제약).

---

## 5. 배경과 스크롤

- 네임테이블 하나가 32x30 타일 = 화면 한 장.
- iNES 헤더는 **세로 미러링**이라, 네임테이블 두 장이 **좌우로** 붙어 있다.
- 그래서 `bg_tile(x, y, ...)`의 `x`는 **0~63**이다. 32 이상이 오른쪽 화면.
  `bg_attr`/`bg_meta`의 `cx`는 0~31.
- `scroll_set(x, y)`의 `x`는 `u16`, 0~511. 런타임이 매 NMI마다 다시 쓴다.
- 가로 스크롤 게임은 화면 밖(오른쪽 네임테이블)에 미리 그려 두고 스크롤하면 된다.
- 세로 스크롤은 이 미러링에서 지원하지 않는다.

## 6. 고정소수점

부동소수점은 없다. 1/16픽셀(12.4 고정소수점)을 쓴다.

```c
u8 x;            /* 픽셀 */
u8 xsub;         /* 1/16 픽셀 */
i8 vy;           /* 1/16 픽셀 / 프레임, 위가 음수 */

#define SUB_PX     16
#define WALK_SPEED 20    /* 1.25 px/frame */
#define GRAVITY     3    /* 0.1875 px/frame^2 */
#define JUMP_SPEED 72    /* 4.5 px/frame 상승 */
#define MAX_FALL   64    /* 종단 속도 4 px/frame */
```

한 프레임 이동:

```c
u8 sub;
sub  = xsub + WALK_SPEED;
x    = x + sub / SUB_PX;    /* 정수부만 픽셀로 */
xsub = sub & 15;            /* 나머지는 다음 프레임으로 */
```

**한 픽셀씩 나눠서 움직이고 매 칸 충돌을 검사하라.** 한 번에 여러 픽셀을 더하면
벽을 통과한다. `examples/platformer.c`의 `move_hero_x`가 그 방식이다.

속도가 프레임당 1픽셀을 넘으면 `while (steps > 0)` 루프로 한 칸씩 전진시킨다.

## 7. 사운드

채널은 4개다. 동시에 낼 수 있는 소리가 그게 전부다.

| 채널 | 쓰임 | 비고 |
|------|------|------|
| 펄스 1 | 멜로디 | |
| 펄스 2 | 화음 | **효과음이 재생 중이면 빌려 간다** |
| 삼각파 | 베이스 | 음량 조절이 안 된다 (켜짐/꺼짐만) |
| 노이즈 | 타악기 | 음정이 아니라 음색 0~13 |

- `sfx_play()`는 펄스 2를 빌리고, 끝나면 곡이 다음 행에서 되찾는다.
- 곡은 끝나면 처음으로 되돌아간다.
- DMC(샘플) 채널은 지원하지 않는다.

---

## 8. 타이밍

- NTSC 60프레임/초. `wait_vblank()`가 한 프레임이다.
- CPU는 약 1.79MHz. 한 프레임에 대략 **29780 사이클**.
- 한 프레임 안에 못 끝내면 프레임을 건너뛴다(게임이 느려진다).
- 무거운 것들:
  - 16비트 곱셈·나눗셈 (수백 사이클)
  - 큰 배열 순회
  - `bg_map()` / `bg_clear()` (화면 한 장 분량)
- 매 프레임 도는 루프에서는 16비트 나눗셈을 피하라. 2의 거듭제곱으로 나누면
  시프트가 되어 훨씬 싸다.

---

## 9. 매퍼

NROM-256(iNES 매퍼 0) 고정이다. PRG 32KB, CHR 8KB, 뱅크 스위칭 없음.

32KB가 모자라면:
- `const` 데이터를 압축하거나 줄인다 (맵을 메타타일로, 반복 구간을 함수로)
- 스테이지 데이터를 생성 코드로 대체한다

매퍼를 늘리지 않는 이유는 `docs/agent/PLAN.md` §6에 있다.
